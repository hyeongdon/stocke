# PRD: 상따(상한가 따라잡기) 돌파매매 · 멀티게이트

> **상태**: Decisions locked (2026-07-16)  
> **작성일**: 2026-07-16  
> **대상 시스템**: stocke 자동매매 (`AutoTradeScanner` → `BuyOrderExecutor` → `StopLossManager`)  
> **관련 코드**: `utils/auto_trade_engine.py`, `managers/auto_trade_scanner.py`, `core/models.py` (`AutoTradeSettings`)

---

## 0. 한 줄 결론

**멀티게이트는 유용하다.** 지금 파이프라인은 “거래대금 후보 → AND 조건 하나(게이트) → 공통 트레일 청산”이라, 상따처럼 **빠르고·세고·짧게** 먹는 진입을 넣으면 기존 모멘텀 진입과 조건이 서로 방해한다.  
게이트를 **이름 있는 패키지 2개**(기존 / 상따)로 나누고, **슬롯·비중만 공유**하는 방식이 이 코드베이스에 가장 잘 맞는다.

## 1. 지금 프로그램이 실제로 하는 일 (쉬운 그림)

```
관심종목 + 거래대금상위(ka10030) + (선택)키움 조건식
        │
        ▼  스캐너 약 60초마다
가격·등락률 필터
        │
        ▼
진입 게이트 (켜져 있으면 AND 묶음 1개)
  · 시가 위?  · VWAP 위?  · 당일 위치?  · 거래량비?
        │
        ▼
매수 신호 → 주문 실행기 → 포지션
        │
        ▼
스탑·트레일링·장마감청산 (전 포지션 공통 설정)
```

### 1.1 스크리닝 (후보 모으기)

| 소스 | 실제 동작 | 비고 |
|------|-----------|------|
| 거래대금 상위 | `get_volume_rank(sort_tp="3")` — **당일 거래대금순** | 상위 N(기본 50) |
| 키움 조건식 | `screener_condition_names`에 이름 나열 | 여러 개 가능, 합집합 |
| 관심종목 | `watchlist_codes` | 항상 포함 가능 |
| 분봉 거래대금 많은 순 | **없음** | 분봉은 VWAP·차트용만 |

스크리너 하드필터: ETF/ETN·스팩·우선주·정리매매 제외, 거래량 하한, PER 비정상 제외 등.

### 1.2 진입 게이트 — “사실상 하나”

코드상 `check_entry_gate()` **함수는 하나**이고, 안쪽은 켜진 조건들의 **AND**다.

| 설정 키 | 의미 |
|---------|------|
| `use_entry_gate` | 게이트 전체 on/off |
| `require_above_open` | 현재가 ≥ 당일 시가 |
| `require_above_vwap` | 현재가 ≥ 당일 5분 VWAP |
| `day_position_min` / `max` | 당일 저~고 구간에서 가격 위치 |
| `volume_ratio_min` | 전일 대비 당일 거래량 비율 |

게이트 밖에도 공통 필터가 있다: `buy_below_price`, `min_change_rate_buy`, 매매시간, 일일손익한도, 동시보유 슬롯 등.

→ 사용자 감각(“진입게이트가 하나”)과 **코드가 일치**한다. OR로 “이 스타일 또는 저 스타일”을 고르는 구조는 **아직 없다**.

### 1.3 청산 — 스탑 트레일링 (공통)

`StopLossManager`가 보유 전 종목에 동일 규칙을 적용한다.

- 익절 구간 도달 → 트레일 무장(`trailing_armed`)
- 고점 대비 `trailing_stop_pct` 하락 / 고정손절 / (옵션) ATR·이익잠금 / 장마감 청산
- 설정은 `AutoTradeSettings` **한 줄(싱글톤)** 에 모여 있고, 포지션별 전략 태그는 약하다.

### 1.4 비중·슬롯 (이미 있는 안전장치)

| 설정 | 기본값(모델) | 상따에 바로 쓸 수 있는 점 |
|------|--------------|---------------------------|
| `max_concurrent_positions` | 2 | “4종목 중 1~2만” → **슬롯 1~2**로 맞추면 됨 |
| `sizing_method` FIXED / PYRAMIDING | FIXED | 상따는 **작은 FIXED** 권장 |
| `initial_min/max_amount` | 200만 / 500만 | 상따 전용 소액 구간 분리 필요 |
| `cash_reserve_pct` | 10% | 현금 버퍼 유지 |
| `max_daily_buys` | 10 | 상따 과매수 방지에 유용 |
| `trade_start_time` | **10:00** | 상따는 보통 **09:00대**가 핵심 → **충돌** |

## 2. 왜 상따가 지금 게이트와 안 맞나

상따(상한가 따라잡기)의 본질:

1. **시초~오전**에 강한 수급으로 **상한가(또는 근접) 방향으로 돌파**하는 종목
2. 거래대금·분봉 거래대금이 **갑자기** 붙음
3. 진입은 **짧고 공격적**, 실패 시 **빠른 손절**, 성공 시 **짧은 트레일**
4. 비중은 **작게**, 종목 수는 **소수(1~2)**

지금 게이트는:

- “시가 위 + VWAP 위 + 당일 위치 …”처럼 **이미 오른 뒤의 품질 확인**에 가깝다
- 기본 매매 시작이 **10:00**이라 상따 골든타임을 놓치기 쉽다
- **상한가 가격·근접도·돌파 구조** 계산이 **없다**
- **분봉 거래대금 랭킹**이 **없다**
- 청산 파라미터가 **전 전략 공통**이라, 상따용 타이트 트레일을 켜면 기존 종목도 같이 바뀐다

그래서 “게이트 조건만 조금 더 세게”로는 상따가 안 나오고,  
“상따 조건으로 게이트를 바꾸면” 기존 거래대금 모멘텀 전략이 망가진다.  
→ **멀티게이트(또는 전략 프로필 2개)** 가 필요한 이유다.

## 3. 멀티게이트, 쓸 만한가? (제품 판단)

### 3.1 결론: **예, 유용하다 — 단, “게이트만 OR”가 아니라 “전략 프로필”로**

| 방식 | 설명 | 이 코드에 맞나 |
|------|------|----------------|
| A. 조건만 OR | (시가돌파) OR (VWAP) OR (상한가근접) | 신호 품질 저하, 디버깅 어려움. **비추천** |
| B. 게이트 패키지 2개 | `legacy_momentum` / `sangtta_breakout` 각각 AND 묶음. 후보가 **하나라도** 통과하면 진입, 신호에 `strategy` 태그 | **추천 (1차)** |
| C. 완전 이중 설정 | 전략별 스크리닝·사이징·청산·시간대 전부 분리 | 이상적이나 DB·UI 공수 큼. **2차** |

**1차 권장: B**(확정)

- 스크리닝 후보는 지금처럼 공유(거래대금 + 조건식 + 관심)
- 진입만 **패키지 A 또는 패키지 B**로 판정
- 슬롯·일일한도·현금예비는 **포트폴리오 공통**
- 상따 신호는 `additional_data.strategy = "sangtta"`로 남김 (체크리스트·대시보드 추적)

### 3.2 슬롯·쿼터 (확정)

| 항목 | 확정값 | 비고 |
|------|--------|------|
| 총 동시 보유 | `max_concurrent_positions = 5` | API·스캔 부하 크면 **4로 하향** 운영 |
| 상따 쿼터 | `sangtta_max_slots = 2` | 나머지 슬롯은 legacy 등 공용 |
| 종목당 금액 | 상따: 소액 FIXED | 비중은 슬롯+금액으로 제한 |

예시 (총 5 / 상따 ≤2):

- 상따 2 + legacy 3  
- 상따 1 + legacy 4  
- 상따 0 + legacy 5  

→ “상따만 소수”는 **쿼터 2**로 고정하고, 총량 5는 부하 보고 4로 조정 가능.

## 4. 제품 목표 (Goals)

### 4.1 목표

1. **상따형 돌파** 후보를 장초·오전에 잡고, **소수·소액**으로만 진입한다.
2. 기존 **거래대금 모멘텀 + 트레일** 전략은 유지한다 (설정 충돌 없이).
3. 진입·미진입 이유를 **체크리스트**로 설명 가능하게 한다 (지금 `buy_condition_checks` 패턴 확장).
4. API 한도·스캔 주기 안에서 **실전 가능한** 타이밍을 보장한다.

### 4.2 비목표 (Non-goals, 1차)

- 완벽한 상한가 예측 / 테마 자동 매칭
- 틱 단위 HFT
- 완전 자동 백테스트 엔진 (별도 `BACKTEST_PLAN` 참고, 1차 범위 밖)
- 전략 프로필 10개 이상

### 4.3 성공 지표 (초안)

| 지표 | 1차 목표 |
|------|----------|
| 상따 신호의 게이트 통과 로그 | 종목·시각·근접도·분봉대금 기록 100% |
| 상따 동시 보유 | ≤ `sangtta_max_slots` |
| 상따 평균 보유시간 | (운영 후 측정) 예: 당일 청산 비중 ≥ X% |
| 기존 전략 회귀 | 상따 OFF 시 기존 스캐너 동작 동일 |
| API 429 / 스캔 지연 | 장중 스캔 1사이클 ≤ 허용 예산 (섹션 7) |

## 5. 상따 돌파 정의 (제품 스펙)

“강한 시세로 시가에서 돌파해 상한가를 따라잡는 종목”을 **측정 가능한 조건**으로 쪼갠다.

### 5.1 유니버스 (후보) — 전략별로 소스를 분리

**핵심 전제:** 상따(급등)는 **시총 작은 종목**에서 자주 나오고, **당일 거래대금 순위에는 잘 안 잡힌다.**  
거래대금 상위는 대형·중형 회전 종목 위주라, 상따 유니버스로 쓰면 **놓치는 비율이 높다.**

| 전략 | 유니버스 소스 | 비고 |
|------|---------------|------|
| `legacy_momentum` | 기존 **거래대금 상위** + (선택) 조건식 + 관심 | 지금 파이프라인 유지 |
| `sangtta_breakout` | **전용 키움 조건식** (필수) | 거래대금순과 **합치지 않음** (1차) |
| (선택) | 관심/테마 워치 | 수동 보조 |

상따 조건식 설계 방향 (소형주 급등) — **확정값 반영**:

1. **시가총액 ≤ 3,000억** (확정)  
2. **등락률 진입 밴드 +15% ≤ 등락 ≤ +19%** (확정) — 상한가 미도달  
3. **시가 대비** 양봉/돌파 (현재가 ≥ 시가, 또는 시가 대비 ≥ 3%)  
4. **거래량·대금은 “순위”가 아니라 “상대·절대 하한”**  
   - 전일 대비 거래량 ≥ 2~3배, 또는 당일 거래대금 ≥ N억  
   - “거래대금 상위 50” 같은 **절대 순위 조건은 쓰지 않음**  
5. (가능하면) **분봉 거래량/대금 급증** — 순간 수급  
6. 관리·투자주의·우선주·ETF/ETN·스팩 제외  
7. **이미 상한가인 종목 진입 금지** (확정)  

→ 프로그램 쪽은 `screener_condition_names`와 **별도**로 `sangtta_condition_names`를 두고,  
상따 게이트는 **그 조건식 결과만** 돌린다. 거래대금 스크리너와 섞지 않는다.  
→ 조건식은 **제공 예정** (HTS에서 위 조건으로 작성 후 이름 등록).

자체 분봉 스코어는 여전히 가능하지만, **입력 풀이 조건식 통과 종목(보통 수~수십 개)** 일 때만 의미 있다.  
거래대금 Top50 위에서 스코어를 돌려도 상따 종목이 풀에 없으면 소용없다.

### 5.2 상따 게이트 패키지 `sangtta_breakout` (AND — 확정 반영)

| # | 조건 | 확정/기본값 | 데이터 |
|---|------|-------------|--------|
| S1 | 매매 시간대 | **09:05** ~ (종료는 운영값, 예: 11:00) — **전략별 시간** | 시계 |
| S2 | 전일대비 등락률 | **+15% ≤ 등락 ≤ +19%** | 현재가 |
| S3 | 시가 대비 상승 | ≥ 3% **또는** 시가 위 유지 | 일봉 open |
| S4 | 상한가 미도달 | 등락 밴드가 곧 “근접 구간”; 상한가 가격 미만 | 상한가 계산 |
| S5 | 돌파 확인 | (선택) 직전 N분 고가 갱신 등 | 1분/5분봉 |
| S6 | 수급 | **전용 조건식 통과**가 1차 필터 | 조건식 |
| S7 | 과열 컷 | **이미 상한가 → 진입 금지** | 현재가·상한가 |
| S8 | (선택) VWAP | 상따는 끄거나 약하게 | 5분 VWAP |

**상한가 가격**: 전일종가 기준 ±30%(코스피/코스닥 일반) 등 시장 규칙을 코드로 계산하거나, API 제공 필드를 쓴다.  
→ **현재 코드에 상한가 필드/계산이 없음 = 1차 필수 개발 항목.**

**전략별 매매 시작 시간 (확정 요구)**  
지금 `trade_start_time`은 전역 1개라 상따(09:05)와 legacy(장 개시 후 ~17분, 예: **09:17** 또는 현재 운영값)를 동시에 맞출 수 없다.  
→ `sangtta_trade_start_time` / `legacy_trade_start_time`(또는 전략별 윈도우)로 **분리**한다. 엔진 기동 시각과 신규매수 허용 시각을 전략 키로 분기.

### 5.3 기존 게이트 패키지 `legacy_momentum` (유지)

지금 `check_entry_gate`의 AND 묶음을 그대로 패키지화.

- `require_above_open`, VWAP, day_position, volume_ratio_min …
- 시간대: **legacy 전용** 시작~종료 (현행: 장 개시 후 ~17분 기점, 예 **09:17** — 운영값 유지). 상따 **09:05**와 분리.

### 5.4 진입 판정 의사코드

```
for stock in universe:
  if legacy_enabled and passes(legacy_momentum):
      emit signal(strategy="legacy")
  elif sangtta_enabled and passes(sangtta_breakout):
      emit signal(strategy="sangtta")
  # 둘 다 통과하면: 우선순위 정책 (아래)
```

**동시 통과 시 우선순위 (권장)**: `sangtta` > `legacy` (같은 종목 이중 신호 방지).  
이미 HOLDING/슬롯 예약이면 스킵 (기존 로직 재사용).

### 5.5 청산 (확정 — 상따 우선순위)

상따 청산은 아래 **우선순위로 평가**한다. (실전 수치·SOFT 민감도는 장중 튜닝)

```
1) 상한가 이탈 / 급락룰     ← 구조 파괴 (최우선, HARD/SOFT)
2) 고정 손절 · 일일손실한도 ← 계좌·포지션 리스크 한도
3) 트레일링 스탑            ← 이익 보호
4) 장마감 청산              ← 당일 청산 전제
```

**검토 의견 (채택):** 순서가 맞다.  
- 이탈·급락을 트레일보다 앞에 두는 것이 상따 논리에 부합한다.  
- **일일손실한도**는 포지션 단위 청산이 아니라 보통 **자동매매 전체 중단(킬스위치)** 에 가깝다 → 구현 시 “해당 포지션 매도”가 아니라 `disable_auto_trade`와 구분해서 둔다.  
- 고정손절 vs 트레일 순서는 기존 `StopLossManager`와 같게 유지하면 된다.  
- 적정 %는 **실매매·로그로만** 확정 가능 → Phase 0/1에서 사유별 발화 횟수를 남긴다.

| 규칙 | 정의 | 비고 |
|------|------|------|
| 상한가 이탈 | 당일 상한가 터치 후 HARD/SOFT 임계 | 상한가 가격 계산 필요 |
| 급락룰 | 당일고(또는 단기고) 대비 HARD/SOFT | VI 없음 |
| 고정손절·일일한도 | 기존 설정 재사용 | 일일한도는 글로벌 중단 |
| 트레일 | 기존 trailing | 상따도 1차는 공통 파라미터 가능 |
| 장마감 | `liquidate_time` | 당일청산 |

#### 노이즈 제거 (HARD/SOFT + soft 2회 — 확정)

지금 `StopLossManager`는 약 **30초 폴링**이다.

```
signal = classify(price):
  HARD  — 확실히 깨짐  → 이번 폴링에서 즉시 매도
  SOFT  — 경계선       → warn_count += 1; warn_count >= soft_confirm_polls 이면 매도
  NONE  — 정상         → warn_count 리셋
SOFT 대기 중 HARD로 악화되면 즉시 매도
```

| 구분 | 상한가 이탈 예시 | 급락룰 예시 | 동작 |
|------|------------------|-------------|------|
| **HARD** | `현재가 ≤ 상한가 × 0.97` | 당일고 대비 **≤ −5%** | **즉시 매도** |
| **SOFT** | `상한가×0.98 ~ 0.97` | 당일고 대비 **−3% ~ −5%** | **연속 2회** 유지 시 매도 |
| **NONE** | `현재가 > 상한가 × 0.98` | 당일고 대비 **> −3%** | 카운트 리셋 |

→ SOFT만 재확인. HARD는 기다리지 않음.  
→ `soft_confirm_polls = 2` (확정). 30초 주기면 SOFT 청산까지 최대 ~60초 지연 가능 — HARD 임계를 너무 멀리 두지 않는 것이 중요.

**추가로 쓰면 좋은 필터**

| # | 방법 | 내용 |
|---|------|------|
| 1 | 충분 이탈폭 | soft/hard를 %로 충분히 |
| 2 | HARD/SOFT 2단 | 위 표 |
| 3 | 기준가 안정화 | 당일고·(선택) 1분 종가 |
| 4 | 호가 버퍼 | 저가주 N호가 |
| 5 | SOFT 중 HARD 즉시 | 물림 방지 |

**운영 기본값 (확정·튜닝 가능)**

| 파라미터 | 값 | 의미 |
|----------|-----|------|
| `limit_break_soft_pct` | 2% | 상한가 대비 −2%부터 SOFT |
| `limit_break_hard_pct` | 3% | −3%부터 즉시 |
| `sharp_drop_soft_pct` | 3% | 당일고 −3% SOFT |
| `sharp_drop_hard_pct` | 5% | 당일고 −5% 즉시 |
| `soft_confirm_polls` | **2** | SOFT **연속 2회** 확인 후 매도 |

**비범위:** VI 발동/해제 청산은 구현하지 않는다. 급락·이탈로 대체.

### 5.6 사이징 (1차)

| 항목 | 상따 | 기존 |
|------|------|------|
| 방법 | FIXED 소액 | 기존 FIXED/PYRAMIDING |
| 금액 | `sangtta_buy_amount` (신규) 또는 min(기존 min, 고정 소액) | 기존 |
| 슬롯 | `sangtta_max_slots = 2` (총 보유 5) | 나머지 공통 슬롯 |

역피라미딩(등락 클수록 금액↓)은 상따에도 논리적으로 맞지만, **1차는 FIXED 소액**이 운영·검증이 쉽다.

## 6. 개발 진행 방향 (로드맵)

### Phase 0 — 관측만 (위험 없음, 1~2일)

- 상따 후보 **알림/로그 전용** (매수 OFF)
- 계산: 상한가 근접도, 시가 대비 %, (가능하면) 분봉 대금 요약
- 대시보드 또는 활동 로그에 `strategy=sangtta_candidate` 표시
- **완료 기준**: 실장 2~3일간 “잡고 싶은 종목”이 후보에 들어오는지 육안 검증

### Phase 1 — 게이트 패키지 + 소액 실매수 (핵심 PR)

1. `check_entry_gate`를 `evaluate_gate_pack(pack_name)` 형태로 리팩터 (동작 동일 유지)
2. `sangtta_breakout` 패키지 추가 + 설정 플래그
3. 신호 `additional_data`에 `strategy` 기록
4. `max_concurrent_positions=5`, `sangtta_max_slots=2`, `sangtta_buy_amount`, **전략별** `sangtta_trade_start_time`(09:05) / legacy 시작 시각  
5. 진입 밴드 +15~+19%, 시총≤3000억, 상한가 진입 금지  
6. 체크리스트(`buy_condition_checks`)에 상따 항목 추가  
7. **완료 기준**: 상따 OFF 시 회귀 / ON 시 슬롯·시간·밴드 준수

### Phase 2 — 유니버스 (전용 조건식)

- `sangtta_condition_names`에 **제공 예정인 전용 조건식** 연결 (시총≤3000억, 등락 15~19% 등 HTS와 맞춤)
- (선택) 조건식 통과분만 분봉 스코어 재랭킹
- `/stocks/surge`는 참고용, 필수 아님

### Phase 3 — 상따 청산 우선순위 (확정)

- 포지션에 `strategy_key` 저장
- `StopLossManager` 평가 순서 (상따):
  1. **상한가 이탈 / 급락룰** (HARD 즉시, SOFT는 `soft_confirm_polls=2`)
  2. **고정 손절 · 일일손실한도** (일일한도는 글로벌 중단)
  3. **트레일링 스탑**
  4. **장마감 청산**
- **VI 연동 없음**

### Phase 4 — 운영 고도화

- 파라미터 대시보드 UI
- 간단한 당일 리플레이 / 검증 페이지 연동
- API 예산 대시보드 (스캔당 호출 수)

## 7. 기존 구현 제약 · 고려사항 (상세)

### 7.1 아키텍처 제약

| 제약 | 영향 | 대응 |
|------|------|------|
| `AutoTradeSettings` **싱글톤** | 전략별 설정이 한 테이블에 섞임 | 1차: 컬럼 추가 / JSON 필드. 2차: 전략 설정 테이블 |
| 게이트 함수 1개 + AND | 스타일 충돌 | 게이트 패키지화 |
| 청산 파라미터 전역 | 상따 타이트 트레일 불가(1차) | 슬롯·금액으로 먼저 제한 → Phase 3 |
| 신호 소스 여러 개 공유 | `strategy_manager`·조건식·스캐너가 같은 `PendingBuySignal` | `strategy` 태그 + 슬롯 계산 통일 |
| 스캔 주기 ~60초 + 게이트당 sleep | 상한가 추격은 초 단위로 놓칠 수 있음 | 상따 윈도우만 후보 축소·조건식 우선·sleep 차등 |

### 7.2 데이터·API 제약

| 제약 | 영향 | 대응 |
|------|------|------|
| 키움 REST 분당 호출 한도 (~18~20/분) | 종목마다 일봉+5분봉 게이트는 비쌈 | 상따는 **조건식 1회**로 1차 필터 → 소수만 차트 검증 |
| 분봉 거래대금 **랭킹 API 미사용** | “분봉대금 많은 순” UX와 불일치 | HTS 조건식 또는 상위 N 자체 스코어 |
| 상한가 가격 **미구현** | 상따 핵심 지표 없음 | Phase 1 필수 |
| 차트 캐시 TTL ~수 분 | 돌파 타이밍 지연 | 상따 경로 캐시 TTL 단축 또는 우회 |
| 기본 `trade_start_time=10:00` | 장초 상따 불가 | 상따 전용 윈도우(09:05~) vs 엔진 기동 시각 분리 설계 |

### 7.3 리스크·운영 제약

| 제약 | 영향 | 대응 |
|------|------|------|
| 상따는 변동성·허매수·상한가 잔량 소진 | 손실 속도 빠름 | 상따 쿼터 2, 소액, 일일매수·일일손실 한도 |
| 시장가 기본 | 슬리피지 | 상따만 지정가/최유리지정 검토 (2차) |
| 장마감 청산 `liquidate_time` | 오버나잇 방지에 유리 | 상따는 **당일청산** 전제와 잘 맞음 |
| PER/ETF 필터 | 일부 테마주 탈락 가능 | 상따 유니버스에서 필터 완화 여부 명시적 결정 |
| 동시 보유 슬롯 = HOLDING + 미체결 예약 | 미체결이 슬롯 먹음 | 기존 `prune_stale_buy_slot_reservations` 유지·모니터링 |

## 11. 권장 실행 순서 (팀용 한 장)

1. 멀티게이트 + **전략별 매수 시작 시각**  
2. 유니버스 분리 — legacy=거래대금, 상따=**전용 조건식(시총≤3000억, 15~19%)**  
3. 슬롯: 총 **5** / 상따 **2** (부하 시 총 4)  
4. Phase 0으로 조건식·밴드 검증 → Phase 1 소액 실매수  
5. Phase 3 청산: **이탈/급락(SOFT 2회) → 손절·일일한도 → 트레일 → 장마감**  
6. VI·분봉 전수 스캔 없음  

이 방향이 현재 stocke 구조를 깨지 않으면서 “시가 강한 상따 / 쿼터 2 / 전략별 시간”에 맞춘다.
